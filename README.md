## 📖 介绍

群友天天问「现在有啥活动」「这个还剩几天」，问完还要挨个催？

这个插件把**原神、崩坏：星穹铁道、绝区零**当前版本的活动抓下来，在群里展示活动名称和剩余天数，并且**按「群 + 人 + 活动」分别记录完成状态**：

- 群友发了「已完成 1」之后，**只有活动 1** 不再 @ 他，其他活动照常提醒；
- 不同群、不同人的完成进度互相独立，不会串；
- 活动数据定时自动更新，跟着游戏版本走，不用手动维护。

## ✨ 功能

- 🗓 **活动总览**：三个游戏的活动一屏看完，带版本号、版本剩余天数和每个活动的剩余天数
- ⏰ **加急标记**：默认 3 天内结束的活动会带 ⏰，一眼看出先做哪个
- ✅ **分开记录完成**：`已完成 1 3`、`已完成 幽境危战`、`已完成 原神`、`已完成 全部` 都行，按人按活动单独存
- 📢 **每日推送**：每个群可以自己设时间（默认 21:00），到点播报活动并 @ 出「这个活动还没做」的人
- 🙋 **谁都能拉人进名单**：群友发 `活动关注 @小明` 就把 TA 加进提醒名单，**不需要群管权限**，从没用过机器人的人也能被 @ 到
- 🙅 **已完成的不会被 @**：推送时按活动分组列 @ 名单，全部做完的人一个都不 @；活动太多时自动合并成一行，不会刷屏
- 🔕 **个人免打扰**：群友自己可以关掉被 @
- 🔄 **自动更新**：后台定时拉取（默认 60 分钟），查询时也有缓存 TTL（默认 30 分钟），保证看到的是最新活动
- 🛠 **可手动修正**：数据源抽风或者少活动时，编辑 `override.json` 就能补/改/删，无需改代码
- ⚙️ **全命令式配置**：推送时间、加急天数、名单上限、谁能改设置……全部用 `活动设置` 改，存在数据文件里，改完立刻生效，**不用动 `.env` 也不用重启**

## 💿 安装

<details open>
<summary>使用 nb-cli 安装</summary>

在 nonebot2 项目的根目录下打开命令行，输入：

```bash
nb plugin install nonebot-plugin-hoyo-events
```

</details>

<details>
<summary>使用包管理器安装</summary>

```bash
pip install nonebot-plugin-hoyo-events
# 或者
poetry add nonebot-plugin-hoyo-events
# 或者
uv add nonebot-plugin-hoyo-events
```

然后在 `pyproject.toml` / `bot.py` 里加载：

```python
nonebot.load_plugin("nonebot_plugin_hoyo_events")
```

</details>

需要 `nonebot-adapter-onebot`（OneBot V11）以及 `nonebot-plugin-apscheduler`、`nonebot-plugin-localstore`，它们会在安装本插件时一起装上。

## ⚙️ 配置（全部用命令改，不用碰配置文件）

所有设置都存在数据文件里、用命令改，**改完立刻生效，不用重启**。每条设置都是按群独立的。

| 命令 | 说明 | 默认 |
|:---|:---|:---|
| `/活动设置` | 查看本群全部设置（标了「已改」的是自己改过的） | - |
| `/活动设置 帮助` | 列出所有可改项 | - |
| `/活动设置 推送 开\|关` | 每日推送开关 | 关 |
| `/活动设置 时间 21:30` | 推送时间 | 21:00 |
| `/活动设置 加急天数 5` | 剩余几天内加 ⏰ | 3 |
| `/活动设置 每游戏条数 8` | 每个游戏最多列几条 | 20 |
| `/活动设置 单条@上限 10` | 一次最多 @ 几人（按人=人数，按活动=每个活动的人数） | 15 |
| `/活动设置 @方式 按人\|按活动` | @ 名单的排列方式 | 按人 |
| `/活动设置 推送@行数 8` | 推送里最多几个活动单独列 @ | 12 |
| `/活动设置 查询时@ 开` | 发 `/活动` 时是否顺带 @ 未完成的人 | 关 |
| `/活动设置 允许@加人 关` | 是否允许「活动关注 @某人」 | 开 |
| `/活动设置 名单上限 30` | 本群提醒名单人数上限 | 50 |
| `/活动设置 权限 群管\|所有人` | 谁能改这些设置、开推送 | 群管 |

超管还能改全局项（对所有群生效）：

| 命令 | 说明 | 默认 |
|:---|:---|:---|
| `/活动设置 全局 缓存 1800` | 查询时的数据缓存（秒） | 1800 |
| `/活动设置 全局 刷新 60` | 后台自动刷新间隔（分钟），`0` 关闭 | 60 |
| `/活动设置 全局 数据源 <url>` | 换一个活动数据源 | SRA 公共 API |

> 想一次性放开权限（不用每次找群管）：让超管发 `/活动设置 权限 所有人`，之后任何群友都能改本群设置、开推送。

### 出厂默认值（可选）

`.env` 只是「出厂默认值」，不写也能跑。只有在你想改**所有群**的初始值时才有必要动它：

| 配置项 | 默认值 | 说明 |
|:---:|:---:|:---|
| `HOYO_EVENTS_ENABLED` | `true` | 是否启用插件 |
| `HOYO_EVENTS_PUSH_TIME` | `21:00` | 群没单独设置过的推送时间 |
| `HOYO_EVENTS_PUSH_DEFAULT_ENABLED` | `false` | 新群默认是否开推送 |
| `HOYO_EVENTS_REMIND_DAYS` | `3` | 默认加急天数 |
| `HOYO_EVENTS_MAX_EVENTS` | `20` | 默认每游戏条数 |
| `HOYO_EVENTS_MAX_WATCH` | `50` | 默认名单上限 |
| `HOYO_EVENTS_PUSH_ADMIN_ONLY` | `true` | 默认只让群管改设置 |
| `HOYO_EVENTS_API_BASE` | SRA 公共 API | 默认数据源 |
| `HOYO_EVENTS_HTTP_TIMEOUT` | `15` | 请求数据源超时（秒） |

优先级：**群命令设置 → 全局命令设置 → `.env` / 代码默认值**。

### 关于编号

列表里的 **1、2、3** 是「这次渲染」的编号，会按当前活动列表自动生成，并缓存 6 小时：

- 群友刚发过 `/活动`，就按他这次看到的编号算；
- 如果刚收到过每日推送，也可以直接用推送里的编号；
- 实在记不清，直接发 `/已完成 活动名` 也行（支持模糊匹配）。

### 关于「@ 谁」

插件只 @ **在本群提醒名单里的人**。进名单有两种方式：

1. 自己发过一次插件命令（`/活动`、`/已完成` 等）自动登记；
2. 任何群友发 `/活动关注 @某人` 手动把 TA 加进来 —— 哪怕 TA 从没和机器人说过话。

不想被打扰就发 `/活动免打扰`，或者从名单里退出（`/活动取关`）。

某人被 @ 的条件是：**当前这个活动他还没标记完成**。所以：

| 场景 | 结果 |
|:---|:---|
| 小红一个都没完成 | 每个活动都 @ 她 |
| 小明只完成了活动 1 | 活动 1 不 @ 他，其他活动继续 @ |
| 阿伟全部完成 | 一条都不 @ 他 |
| 阿伟从没发过命令，但被 `/活动关注 @阿伟` 加进名单 | 没做完的活动照样 @ 他 |
| 阿伟下周开了新活动没做 | 新活动继续 @ 他（新活动是新的记录） |

## 🧠 工作原理

1. **数据来源**：默认使用 [SRA 公共 API](https://starrailassistant.top/reference/public-api/) 的 `ys` / `sr` / `zzz` 三个活动接口，免费、无需鉴权，返回当前版本号和每个活动的起止时间（UTC+8）。
2. **定时刷新**：APScheduler 每 `HOYO_EVENTS_REFRESH_INTERVAL` 分钟拉一次；查询时如果缓存超过 `HOYO_EVENTS_CACHE_TTL` 也会先拉一次。拉取失败时沿用上一次的数据，不会把列表清空。
3. **活动身份**：活动以「游戏 + 活动名」生成稳定 ID。
   - 活动延期（只改结束时间）→ ID 不变，已完成的标记保留；
   - 活动复刻（上一期结束后同名活动再来一次）→ 代次 +1，视为新活动，重新开始提醒。
4. **完成状态**：存成 `群 → 人 → 活动` 三层映射，因此天然做到「不同活动分开记」「不同群互不影响」「不同人互不影响」。
5. **推送**：每分钟检查一次各群的推送时间，到点且当天没推过就推；失败会重试，最多 5 次。@ 的目标是本群提醒名单里、且这个活动还没标记完成的人。

数据文件在 NoneBot 的 localstore 目录下（一般是 `data/nonebot_plugin_hoyo_events/`）：

| 文件 | 作用 |
|:---|:---|
| `store.json` | 活动缓存、完成记录、群设置（**含群号和 QQ 号，注意备份与隐私**） |
| `override.json` | 手动修正活动数据 |

### 手动修正活动（可选）

数据源偶尔会晚一步，或者你想加一个数据源里没有的活动，改 `override.json` 即可，下一条命令就生效，不用重启：

```json
{
  "ys": {
    "remove": ["数据源里错的或不想显示的活动名"],
    "patch": [
      { "name": "某活动", "endTime": "2026-12-10T03:59:59" }
    ],
    "add": [
      {
        "name": "自己加的活动",
        "startTime": "2026-11-20T10:00:00",
        "endTime": "2026-12-01T03:59:59",
        "description": "可选"
      }
    ]
  },
  "sr": { "add": [], "remove": [], "patch": [] },
  "zzz": { "add": [], "remove": [], "patch": [] }
}
```

## ❓ 常见问题

**Q：为什么群友明明完成了，还在被 @？**
A：检查是不是在**另一个群**发的 `/已完成`（进度按群保存），或者用 `取消完成` 误撤销过。发 `/未完成` 可以看到当前群的实时状态。

**Q：为什么有人一次都没被 @？**
A：他不在本群提醒名单里。让他发一次 `/活动`，或者任何人发 `/活动关注 @他` 把他加进来。

**Q：我不是群管，能开每日推送 / 改设置吗？**
A：默认只有群管能改。两种办法：
1. 让群管或超管发一次 `/活动设置 权限 所有人`，之后任何群友都能改本群设置；
2. 让群管发一次 `/活动提醒 开`。

不开启推送也能用：发 `/活动 提醒` 会当场 @ 一遍没完成的人。

**Q：别人乱把我加进名单怎么办？**
A：`/活动取关` 退出即可；被 @ 前也可以先用 `/活动免打扰` 静音自己（仍然会记录进度，只是不 @ 你）。

**Q：活动列表里少了某个活动？**
A：数据源以当前版本为主，可能抓取滞后。用 `override.json` 的 `add` 补一条，或者等下一次刷新。

**Q：能只看原神吗？**
A：`/原神活动`，或者 `/活动 原神`。

**Q：推送时间能每个群不一样吗？**
A：可以，`/活动设置 时间 22:30` 是按群保存的，每个群互不影响。

**Q：支持多 bot / 一个 bot 在多群？**
A：推送会遍历当前连上的 OneBot bot，只要有一个在目标群就能发出去；群设置按群号保存，与 bot 无关。
